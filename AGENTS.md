# Agents

## Stack & scope
- Expo (SDK ~58) + Expo Router app targeting **web only** (`app.config.js`: `platforms: ["web"]`, `web.output: "static"`, `bundler: "metro"`, `apiRoutes: true`). UI/state: React 19, React Native Web, NativeWind v4 + Tailwind v3, Zustand. Global CSS: `stylesheets/global.css` (wired in `metro.config.js`).
- Plain JavaScript only (no TypeScript). JSDoc for modules/exports (`@module`, `@typedef`/`@type`, `@param`, `@returns` — never `@example`).
- Supabase-backed: **local** stack for dev/local builds, **hosted** only for Expo Hosting deploys. No cross-environment fallback. Server routes use anon key + forwarded user bearer tokens via `database/instance.js` (RLS enforced); never use/expose a service-role key.
- **Bun (≥1.4.5) is the only runtime.** Install, scripts, tests, CI and Docker all use Bun; there is no npm/`package-lock.json`. The app is a static export, so Bun runs the toolchain.

## Commands
- `bun install` — install from `bun.lock`; `bun run check` — enforce import/layering boundaries; `bun run bun:test` — run Bun tests under `test/`, mirroring root modules. `bun run playwright` / `bun run playwright:test` — invoke Playwright, including the `test/app/*.e2e.js` E2E specs; the config starts the dev server and Caddy and drives HTTPS through `$URL_PROXY_PORT`, with artifacts written outside the workspace.
- `bun run expo` — pass-through to the Expo CLI. `bun run expo:start` / `expo:start:tunnel` — dev server (`URL_PORT` injected by the launcher). `bun run expo:build` — static export into `build/` and copies `png/logo*.png` to `build/client/png/`. `bun run expo:serve` — serve `build/` on `URL_PORT`. Hosted exports pass `--hosted` to the launcher (`bun ./scripts/expo.js export --platform web --output-dir build --hosted`), which forces `EXPO_PUBLIC_SUPABASE_TARGET=hosted` during the export.
- `bun run supabase` — pass-through to the Supabase CLI. Supabase local: `bun run supabase:initialize|start|stop|status|reset|migration`; all invoke `bun x --bun supabase`. Hosted: `supabase:link` (injects `--project-ref` from `.env`) and `supabase:push`; `supabase:reset:remote` drops/reapplies hosted schema then pushes (destructive).
- Docker/app: `bun run docker:build|up|down|logs`, `docker` (full cycle). `bun run caddy` / `caddy:trust`. `bun run opencode`, `bun run skill` (skills in `.agents/skills/`).
- Deploy/ops: `bun run eas` — pass-through to the EAS CLI. `bun run eas:initialize`, `eas:deploy` (builds with `--hosted` and forces `EXPO_PUBLIC_SUPABASE_TARGET=hosted` for the upload), `gh:remote|secrets|deploy`, `gh:workflow:supabase|expo`.
- Every command loads `.env` through a `scripts/*` launcher; never `set -a && . ./.env` in `package.json`.

## Launcher & system conventions
- `package.json` scripts call thin launchers in `scripts/`; each uses `rawArguments()` (original argv order), loads `.env` with `{ optional: true }`, chdirs to the root, and spawns the tool with the merged environment through `system/process.js`.
- `scripts/expo.js` appends `--port` from `URL_PORT` for `start`/`serve` (Expo ignores the port env var) and copies the two logo PNGs into the static export with `system/io.js` + `system/path.js`. `scripts/eas.js` maps `EAS_TOKEN` → `EXPO_TOKEN` and forces the hosted Supabase target on `deploy`. `scripts/supabase.js` injects `--project-ref` for `link` and implements `reset-remote`. `scripts/gh.js` injects `--repo` from `GITHUB_REPOSITORY` for `secret`/`workflow` commands; `scripts/git.js` injects the origin URL and a token credential helper for `push`. `scripts/caddy.js` passes `.env` via the process environment instead of `--envfile`.
- `system/*` modules wrap Node built-ins rather than reimplementing them: `argument.js` → `node:util.parseArgs`, `console.js` → `node:console`, `io.js` → `node:fs`, `path.js` → `node:path`, `process.js` → `node:child_process`, `uri.js` → `URL`. Scripts import only from `system/*`, never `node:*` directly.
- `system/*` uses named ESM exports, no shebangs, and imports Node APIs from `node:*` (named bindings from `node:process` except `signal.js`). Return values are literal data — never `Date`, `URL`, or stream objects. Modules with a real failure path import the matching factory from `errors/` and throw that centralized app error.
- `console.js` exports `info`, `warn`, `error`, `debug`, `trace`; `debug(task, ...args)` times a sync/async task, prints **only** its elapsed duration, returns the result and rethrows failures. `process.js` is synchronous: `exec()` → `{code, stdout, stderr, error}`, `spawn()` → `{code, signal, stdout, stderr, error}`. Launchers time `spawn()` with `debug()` and `exit()` on failure.
- `path.base()` strips the extension; `extension()` has no leading dot; `parent()` is `dirname`. `io.js` exports only `read`/`write` (`read` returns a Buffer without an encoding, which is how logo PNGs are copied); `uri.js` exports `url`, `encode`, `decode`, `encodeUriComponent`, `decodeUriComponent`, `fileUrlToPath`, `pathToFileUrl`.

## Architecture & conventions
- **No absolute paths** in source/config/docs (except `node_modules/`). Do not create `public/`; static icons stay in `png/` (sources in `svg/`).
- Only `/` and `/signin` are public pages. Protected customer UI routes use `app/(customer)/` (`/menu`, `/cart`, `/checkout`) with a `customer`-role guard; visitors sign in with the single shared guest profile (no signup).
- Protected staff UI routes use `app/(staff)/` with a `staff`-role layout guard: `/staff/order` for order taking and `/staff/records` for order logs.
- Protected admin UI routes use `app/(admin)/` with an auth guard (URLs remain `/admin/*`). The profiles audit page lists every seeded profile.
- Routing: Expo Router under `app/` (`api/**/+api.js`, `+not-found.js`, `+html.js`, special `manifest.json+api.js`, `robots.txt+api.js`, `service-worker.js+api.js`). Screens in `screens/` mirror route paths (`*.screen.js` layout modules); reusable UI in `components/`.
- Layers: `app/api/*` thin method wrappers → `endpoints/*` compose middleware/validation/repos/response → `interceptors/*` → `repositories/*` → `database/instance.js`. Client: `services/*` → `stores/*`. Leaf utilities: `cipher/`, `constants/`, `errors/`, `format/`, `helpers/`, `network/`, `stylesheets/`, `validation/`. No barrel `index.js` in `interceptors/` or `endpoints/`.
- DB config/clients: `constants/config.js` is the single source of truth (API endpoints incl. `checkout`, DB target/URLs). `database/instance.js` exports `getDatabaseClient()`, `getDatabaseServerConfig()`, `createDatabaseClient({ accessToken })`.
- Supabase data lives in `supabase/config.toml`, `migrations/*.sql`, `seeds/*.sql` (items + seeded `admin@`, `staff@`, shared `guest@paku-paku.official` accounts). Do not edit `supabase/.temp/` or `.branches/`. Verify schema changes with `bun run supabase:reset` and `bun run expo:build`.
- Local Supabase ports are private: API `54321`, PostgreSQL `54322`, Studio `54323`, Mailpit `54324` — never proxy/tunnel. Dockerized routes reach Kong via `SUPABASE_LOCAL_SERVER_URL` (`http://api.supabase.internal:8000`) on external network `supabase_network_paku-paku` (start `supabase:start` before `docker:up`).
- MCP: `opencode.json` keeps the remote Supabase and Expo MCPs, the GitHub MCP authenticated with `GITHUB_TOKEN` (`oauth: false`), the official local Penpot MCP at `http://localhost:4401/mcp` (self-hosted Penpot; `PENPOT_MCP_TOKEN` and `PENPOT_PAT` live in `.env`), and the official local Playwright MCP (`@playwright/mcp`) configured but not used yet, plus `instructions: ["CONTRIBUTING.md", "DESIGN.md"]` and disabled compaction.
- CI/workflows: `.github/workflows/ci.yaml` runs on pushes, pull requests and manual dispatch; it restores `.env` from `DOT_ENV`, sets up Bun and Caddy, installs Playwright browsers, gates Bun tests at 95% coverage and runs `playwright:test`. `deploy-expo.yml` and `deploy-supabase.yml` also set up Bun, restore `.env` from `DOT_ENV` and trigger on push to `main` or manual dispatch. EAS runs no builds.

## Runtime & deployment notes
- `.env` holds Expo/Supabase public+server config, `EXPO_TOKEN`, `EAS_PROJECT_*`, URL/proxy vars, and `GITHUB_REPOSITORY`/`GITHUB_TOKEN`. Keep it POSIX-compatible (`KEY=value`); `system/environment.js` parses it with `node:util.parseEnv`. `.env` is gitignored — refresh `DOT_ENV` when keys change.
- `Dockerfile` uses `oven/bun:1.4.5-alpine` in both stages, installs with `bun install --frozen-lockfile` and exports with `bun run expo:build`. It defines no CMD: Compose's `server` runs `bun ./scripts/expo.js serve build` and `caddy` runs the HTTPS edge. `build`/`test-unit` one-shot services also use the Bun image.
- `build/`, `node_modules/` and `.expo/` are generated (gitignored); edit source/config/launchers only. `/api/health` returns `{status:"ok",timestamp,uptime}` with `Cache-Control: no-store`.
